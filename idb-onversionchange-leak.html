IndexedDB onversionchange GC Leak

Attaching an onversionchange listener prevents the database connection from being GC'ed.

Opening an IndexedDB database without calling .close() is problematic if the code also attaches an onversionchange event listener.

Because IDBDatabase is an ActiveScriptWrappable, its HasPendingActivity() method tells V8 that the object is still active as long as the connection isn't pending closure and has event listeners attached. This effectively roots the object in C++, preventing GC from ever reclaiming it and closing the connection (even if GC is forced in DevTools).

Click the buttons below to create leaked connections. Observe the memory increase for the browser process via Task Manager. Check the connections remaining open at chrome://indexeddb-internals/#francoisdoray.github.io:443. 

const request = window.indexedDB.open(DB_NAME, 1);

request.onsuccess = (event) => {
  const db = event.target.result;

  // LEAK: As long as this remains open without db.close(),
  // the onversionchange listener keeps the C++ object alive.
  db.onversionchange = () => {
    console.log("Version changed!");
    db.close();
  };
};
