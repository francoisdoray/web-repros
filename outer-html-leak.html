outerHTML Memory Bloat

Strings generated by outerHTML aren't immediately reclaimed

Status: Fixed

Fixed in Blink by Andrey Kosyakov (caseq@) via optimizations to avoid allocating and creating unnecessary GC'ed unions when returning union member types:

  • CL 7629901: Allow native methods to return a union member type instead of a union
  • CL 7634373: Skip union creation for calls always returning a predetermined union member
  • CL 7640493: Do not return a union from HTMLElement::innerText()
  • CL 7640317: Introduce OptimizedReturnProxy to make returning a union cheaper

This page calls outerHTML repeatedly from a high-frequency timer. Each call generates a string owned by a GC'ed object (Oilpan), without accounting for the size of the string as external memory to inform GC. You can observe how the memory grows via Chrome's Task Manager.
